# Institutional Microsoft account readiness — 24 November 2026

Live read-only schema inspection confirmed microsoft_education_accounts and unipathway_microsoft_jobs exist. The Microsoft account onboarding, brand profiles and class templates tables are absent. This explains why optional setup screens must not infer an incomplete account or hide otherwise valid mappings.

Student and lecturer views now explicitly query the authenticated account and centre with a minimum selected field set. Strict receipt validation rejects foreign, conflicting, duplicate and wrong-role mappings. Stale responses are discarded on account/role changes, loading and failure are distinct from no record, and a disabled account never gets a ready label. A stored ready status is not a real Graph or sign-in verification. The old unused onboarding page shares the same component rather than querying a missing table.

The director setup page independently loads centre-scoped account mappings, branding and templates, preserving verified account results when optional tables are missing. It uses the existing provisioning queue and existing worker; no new account provider, licence assignment, secret storage or activation operation was added. Results exceeding 500 records require a paginated report, not silent truncation. No credentials, real accounts, licences or production data were created or changed. Full live Microsoft Graph and role/JWT acceptance remain required, including current fee policy, verified institutional domain, eligible licences, MFA, account lifecycle and authorised administrator handoff.
