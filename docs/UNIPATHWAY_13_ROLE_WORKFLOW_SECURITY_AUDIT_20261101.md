## Shared access model / threat cases

- `RoleGuard` and `verifiedRoleMemberships` check the **active** selected membership. Test emails are examples only: an email address or a role entry in UI is not proof that the account has current access. Actual backend `user_roles`, `profiles.tenant_id`, RLS and protected RPC checks control access.
- Platform Owner and Centre Director access to shared staff dashboards **must not be treated as a substitute for a student's or external partner's role**. For external partners, avoid broad `OR superadmin` data reads without documented platform audit controls.
- Every exposed sensitive table must enforce server-side RLS, not merely client `.eq('tenant_id',...)` filtering. Read error must not become a fabricated zero KPI. Check direct REST, Edge, storage and signed URLs separately.
- Dedicated `SECURITY DEFINER` RPCs require tight EXECUTE grants and explicit actor/centre/record validation; the browser may only request a decision. Never use editable user metadata for permission grants. Verify revocation and stale JWT behaviour.
- No finance, exams, staff invitation, provider lab, certificate, attendance or awarding-body status is fabricated as live because a menu route exists. Disabled/staged screens must explain why.

## Release order and unfinished integration owners

1. **P0 privacy:** Verify hosted RLS/EXECUTE/storage for external EQA, agent applications, employer application counts, student/parent sensitive records and medical data with real centre A/B JWTs. The fixes for EQA, agent, marketing and employer are source only until the correct GitHub PR is merged and the site's deployment is confirmed.
2. **P0 build/CI:** Resolve all exact-head GitHub Actions jobs (typecheck, lint, unit, database PGlite, Edge/Deno, browser, Android, iOS). Regression suite: `src/test/unipathway-cross-role-dashboard-contract.test.ts`.
3. **P1 academic control:** Verify assessment publish → student submission → independent assessor → IQA approval → student result release → guardian consent → EQA sample → allowed appeal. Use actual deployed RPCs and audit rows; prohibit direct status changes.
4. **P1 financial control:** Invoice issuance → card/bank provider confirmation → ledger reconciliation → refunds → verified scholarships/sponsor funding → separately approved agent/university commission records. Reports must use explicit centre/role-scoped exports.
5. **P1 external partner:** First approve institution/employer membership and student consent with expiry; build applicant/referral and communication state machines only after direct JWT/RLS tests. Employer draft publication stays staff-approved.
6. **P2 student experience:** Confirm learning plans, course materials, timetables, Teams classroom invites, assessed tech lab module grant, actual provider resource creation, language lab consent, career and overseas progression guidance with appropriate disclaimers.
7. **P2 marketing/exams:** Add approved email provider with consent + unsubscribe, webinar scheduling, official exam registrations, venue/candidate/invigilator seating, incidents and verified board result imports. Do not substitute internal calendar events or assignment marks.
