# Reviewed lecturer allocation — controlled activation

This source change adds a private centre-scoped module allocation decision. A verified centre director (or a global owner with a selected centre) explicitly checks a particular module against an independently approved, current lecturer competency. The source competency must still match its latest application declaration and the original reviewer must still be authorised in the centre. The module and programme scope, competency snapshot, prior assignment, reviewer, note and time are recorded. No automated equivalence or appointment is inferred.

The server requires the current module revision and scope; prevents self-assignment; checks current or future timetable entries before changing or removing a lecturer; and returns exact idempotent receipts. Once writes are enabled, a trigger prevents direct assignment changes, new preassigned modules and changes to assigned module scope outside the reviewed workflow. Existing assignments are not automatically removed. A changed programme description, revoked competency or expired membership can make a stored decision stale; the current decision read flags drift, but existing LMS access is not automatically revoked by this release. Programme leaders can continue ordinary curriculum work but reviewed allocation is restricted to directors and selected-centre owners. Separate verified module registration/withdrawal enforcement and teaching access revocation remain outstanding.

Install the forward SQL only after accepted onboarding schema and role guards, core learning policies and timetable prerequisites. Both private database gates default off and the frontend independently requires VITE_UNIPATHWAY_REVIEWED_ALLOCATION_ENABLED=true. Coordinate the frontend rollout with read-only verification and write activation; once the database write guard is on, legacy direct writes fail closed. Reconcile existing assignments and review all module creation/edit/schedule flows before enabling. The synthetic two-centre tests are not live JWT/RLS or concurrent timetable acceptance; real provider invitation reconciliation, backup/restore and deployment acceptance are still required. No production mutation or external accreditation claim.
