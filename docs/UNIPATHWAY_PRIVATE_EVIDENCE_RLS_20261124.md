# Private onboarding evidence — production hardening candidate

Live read-only findings, 24 November 2026: the UniPathway cloud database had RLS enabled on kyc_documents, but its legacy insert policy permitted null-tenant owner inserts and did not require pending status. The legacy staff storage SELECT policy checked the role without a centre predicate. The KYC bucket was private, with no bucket-specific size limit. Zero KYC rows and objects were observed during that inspection; repeat the count before deployment. This does not prove anyone exploited these policies.

The forward script replaces metadata grants and policies only on kyc_documents, and replaces the three known KYC storage policies plus restrictive bucket-specific boundaries. Exact current centre membership is required; global owners need a selected centre and have read-only review access. Applicants can insert pending metadata linked to an existing object under their own account prefix. Reviewers must be independently assigned admissions or director staff; they cannot change the owner, centre, evidence path or original file name. Verified records require the reviewer's identity and timestamp. Anonymous access, client deletion and overwrite are blocked. Unlinked uploads remain inaccessible; authorised service-side reconciliation and retention handling are required rather than allowing clients to remove reviewed evidence.

Run the synthetic CI rehearsal with two centres first, then verify current schema, actual policy inventory, column grants, bucket settings, backup/restore and real role JWTs in a controlled deployment transaction. The existing general document and onboarding uploads must be tested with the storage API, including the write-response select and reviewer flow. No claim of malware scanning or provider verification; the bucket size limit is not content inspection. Existing legacy null-tenant or unlinked files require authorised reconciliation, not broader access. No bulk migration, production write or activation performed by this PR.

Other outstanding launch blockers: current_unipathway_tenant_id() helper is absent on the inspected live backend, as are the four onboarding tables and the three scheduling tables. Reconcile dependencies and migration ledger separately; do not rerun the broad historical policy rewrite blindly. Production deployment requires a verified project, approved recovery path, real tenant role acceptance and provider checks.
