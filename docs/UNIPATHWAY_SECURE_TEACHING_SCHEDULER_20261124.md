# Secure teaching scheduling advisory — 24 November 2026

The legacy generative scheduling endpoint is replaced by a disabled-by-default deterministic, read-only candidate evaluator. Activate only after authenticating both centre fixtures and verifying RLS on all source tables. This is an intentional API contract change. No provider or model receives CV, identity, application or availability records.

POST `teaching-scheduler-agent` with a verified JWT and `{moduleId, cohortReference?, requiredSlots:[{date:"YYYY-MM-DD",start:"09:00",end:"09:45",mode:"centre",room:"Room A"}]}`. All times PKT; 1–8 slots, exactly 45 or 90 minutes, approved physical room label required for centre/hybrid. Management is limited to a centre-linked verified director or global superadmin. The server derives the tenant from the caller profile; no caller-selected tenant or lecturer is accepted.

The existing active, independently approved module eligibility table and current lecturer role must match. Candidate availability comes from the saved applicant declaration with explicit Asia/Karachi zone, complete time ranges and delivery mode; it remains self-reported. This avoids guessing the legacy structured staff availability weekday convention. The candidate is screened against visible active recurring timetable records and non-cancelled dated teaching assignments. Exact-count reads over 500 records fail closed rather than silently truncate. Each slot has up to five ranked alternatives, not a combined multi-slot allocation. Current competency reviews, approved availability, future weeks, maximum workload, room capacity, individual learner overlaps and external Teams bookings still require review. No bookings, payroll, grades or other records are written. No autonomous AI scheduling or live deployment is asserted.

Required: exact-head CI; activate only in the correct UniPathway project after a two-centre RLS and real-role test, verify approved roster, confirm API callers have moved to the new contract, check live provider and timetable parity, and run a fresh authorisation review before any optional AI ranking. Model advice must never be treated as an eligibility decision.
