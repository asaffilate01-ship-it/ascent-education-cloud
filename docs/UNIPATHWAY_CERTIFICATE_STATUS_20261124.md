# Public certificate status privacy and UI

This release corrects the legacy public page, which labelled any returned row verified and treated API errors as a missing record. The live schema inspected on 24 November 2026 has a unique certificate_number, status default valid, issue and expiry dates, and a legacy full-row RPC; no certificate rows were observed at inspection.

The new status-only RPC intentionally supports anonymous exact-reference queries. It returns exactly three fields (reference, status, UTC check date), never names, grades, programme metadata, tenant identifiers or timestamps. Revocation, expiry, future/inconsistent dates and missing centre linkage are evaluated server-side. It is not an independent awarding-body or holder identity verification. Direct legacy full-row RPC grants are revoked for public clients; existing staff table permissions and issuance restrictions are otherwise unchanged. Review legacy callers before activation; monitor and rate-limit public queries at the actual gateway because exact references may be guessable. No arbitrary issuance, certificate record creation or payment.

The public page uses an accessible, responsive form, explicit errors, separate unavailable/not-found/revoked/expired/needs-review states and strict response validation. It never falls back to the legacy PII response. Until the new RPC is installed, it shows unavailable. The forward candidate is not a baseline migration. Apply only after confirming production project, actual schema and permissions, backup and recovery, and synthetic plus real public/authorised staff acceptance. No hosted write performed by this PR.
