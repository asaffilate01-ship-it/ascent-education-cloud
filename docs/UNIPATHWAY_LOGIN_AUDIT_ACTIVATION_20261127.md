# Institutional login audit — reviewed follow-up

Requires the approved institutional account/session patch and actual hosted acceptance. Do not apply to another project. The forward patch adds centre and institutional address at the moment of each Auth session event. Historical rows without a recorded centre are not guessed from current profiles.

The review gate starts disabled. An authorised operator must approve an individual current global superadmin, who has an active profile assignment for the exact centre, in the private login_audit_reviewers table. An institutional AAL2 session, live approval and explicit delegation are all required. Ordinary staff, security officers and directors do not automatically receive IP access. Browser users cannot write approvals, event rows or audit history. Each verified read records reviewer, centre, time, period, whether an email filter was used and count returned. The API returns at most 100 recent events for a 7/30/90-day period or exact institutional email; no bulk export or automatic geolocation is included.

Rehearse the patch and extended scripts/test-institutional-auth-db.mjs against the predecessor schema. Check cross-centre and revoked reviewer denial, AAL1 denial, actual Auth session IP and timestamp fields, profile reassignment and retention. Existing security-definer functions and service-role endpoints remain subject to the wider institutional activation review. Verify database advisors and permissions. No hosted gate or delegation is enabled by the repository change.

The Production Readiness panel appears only in institutional mode for a selected verified superadmin with a centre assignment. It submits an explicit review request and fails closed for invalid responses. It is not a complete sign-in history: failed attempts and rejected token issuance belong to the hosted Auth audit logs. IPs can reflect a VPN, proxy or carrier. Do not infer exact physical location. Approve access, retention, deletion, notification and incident response procedures before activation. Avoid sharing the IP viewer or recording credentials in audit notes.
